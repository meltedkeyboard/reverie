Клиент для ролевых чатов на Expo (iOS и веб). Работает напрямую с локальным сервером по OpenAI-совместимому API (LM Studio, llama.cpp, Ollama). Все данные хранятся на устройстве.

## Запуск

```
npm install
npx expo start
```

Приложение открывается в Expo Go. Адрес сервера задаётся в настройках, например `http://100.x.y.z:1234`.

В браузере:

```
npm run web
```

Статическая сборка — `npx expo export --platform web`, результат в `dist/`.

## Структура

- `app/` — экраны (expo-router): список персонажей, чаты персонажа, чат, редактор персонажа, настройки.
- `src/api/llm.ts` — запросы к серверу, разбор SSE, окно контекста (`CONTEXT_WINDOW`, 20 сообщений).
- `src/hooks/useChat.ts` — состояние диалога и стриминг.
- `src/db/` — схема и запросы expo-sqlite (`characters`, `chats`, `messages`, `app_settings`).
- `src/lib/` — аватары, экспорт резервной копии, диалоги, разбор `*действий*`.
- `src/components/` — интерфейсные компоненты.
- `public/index.html` — оболочка страницы для веба, `metro.config.js` — поддержка `.wasm`.

Файлы с суффиксом `.web` — браузерные реализации того же интерфейса: `avatarStore`, `download`, `dialogs`. Остальной код общий.

## Детали

- Персонаж работает как шаблон: с ним может быть сколько угодно чатов. Новый чат начинается с приветствия персонажа. Системный промпт и параметры генерации берутся из персонажа, поэтому его правка действует на все его чаты.
- Чат, в котором пользователь ничего не написал, удаляется при возврате к списку.
- Название чата задаётся вручную или генерируется моделью: автоматически после первого ответа, если названия ещё нет, либо по пункту «Придумать название» в меню чата.
- Под каждым сообщением панель действий: копировать, перегенерировать (у ответа) или изменить (у своего сообщения), меню «…» (на iOS нативное) и переключатель вариантов. Долгое нажатие открывает полный список действий. На iOS выделение текста открывается отдельным листом, потому что долгое нажатие занято меню.
- «Уточнить...» перегенерирует ответ с пожеланием пользователя ("грустнее", "больше удивления"). Пожелание добавляется к последней реплике пользователя как `(OOC: ...)` только в этом запросе и не сохраняется.
- Размышления рассуждающих моделей показываются вживую над ответом (блок раскрывается нажатием), а после ответа остаются свёрнутыми над ним. Они сохраняются для каждого варианта в `messages.thoughts` (JSON вместе с длительностью) и никогда не отправляются обратно в модель. Поддерживаются поля `reasoning_content` и `reasoning` в потоке и теги `<think>` в начале ответа.
- Перегенерировать можно любой ответ: модель получает только переписку до него, новый ответ добавляется вариантом «‹ 2/3 ›», следующие сообщения остаются. «Ответить заново» у сообщения пользователя перегенерирует ответ сразу после него. Все версии лежат в `messages.variants` (JSON), выбранная дублируется в `content`, и дальнейшие ответы строятся на выбранных вариантах.
- Меню у «+», «…» под сообщениями и капсулы с названием чата на iOS нативные (SwiftUI `Menu` из `@expo/ui`): кнопку рисует React Native, а `RNHostView` встраивает её в подпись меню, поэтому меню вырастает из самой кнопки и морфится из неё. У «+» и капсулы стекло Liquid Glass тоже рисует подпись меню. Без модуля `ExpoUI` и в браузере вместо меню открывается лист действий (`src/components/NativeMenu.tsx`).
- На iOS 26 экран чата использует Liquid Glass: вместо размытых полос сверху и снизу плавающие стеклянные кнопки и капсулы (`expo-glass-effect`, кнопки SwiftUI из `@expo/ui`) и градиент по краям. Модули подключаются в `src/lib/nativeUI.ts`, только если есть в сборке; иначе, на старых iOS и в браузере экран выглядит как прежде.
- К сообщению можно прикрепить фото. Оно уменьшается до 1024 px и хранится в базе как JPEG в base64 (в браузере `localStorage` для фото слишком мал). В модель фото уходит в формате OpenAI `image_url`, поэтому нужна модель с поддержкой изображений. Фото повторно отправляются с каждым запросом, пока сообщение остаётся в окне контекста.
- База лежит в Documents iOS. Для аватаров в базе хранится только имя файла.
- HTTP-адреса разрешены через `NSAllowsArbitraryLoads` в `app.json`.
- Экспорт JSON не содержит API-ключ.
- Стриминг использует `fetch` из `expo/fetch`: обычный `fetch` React Native не отдаёт тело ответа по частям. В браузере это стандартный `fetch`.

## Веб

- Сервер модели должен отдавать заголовки CORS, иначе браузер заблокирует запрос: в LM Studio это переключатель в настройках сервера, в Ollama — `OLLAMA_ORIGINS`. Страница по HTTPS не сможет обратиться к серверу по HTTP.
- SQLite работает через WebAssembly и OPFS, аватары лежат в `localStorage`. Данные привязаны к домену и браузеру; `localStorage` ограничен несколькими мегабайтами.
- База доступна только одной вкладке. Вторая вкладка с Reverie покажет ошибку вместо пустого экрана.
- `Alert` и `ActionSheetIOS` в вебе не работают, поэтому диалоги рисует `src/lib/dialogs.web.tsx`.
- Экспорт резервной копии скачивает файл вместо системного окна «Поделиться».
- На клавиатуре Enter отправляет сообщение, Shift+Enter переносит строку.
